# Lattice1 protocol

TypeScript port of the Lattice1 wire protocol from
[ape-grid-lattice](https://github.com/BlockEnthusiast/ape-grid-lattice)
(`ape_grid/protocol/`, `calldata.py`, `client.py`), which is itself a
byte-parity port of GridPlus's MIT-licensed
[gridplus-sdk](https://github.com/GridPlus/gridplus-sdk).

| Module | ape_grid source | gridplus-sdk source |
| --- | --- | --- |
| `constants.ts` | `protocol/constants.py` | `packages/types/src/protocol.ts` |
| `firmware.ts` | `protocol/firmware.py` | `constants.ts` (fw >= 0.15.0) |
| `secureChannel.ts` | `protocol/secure_channel.py` | `util.ts` |
| `encoding.ts` | `protocol/encoding.py` | `protocol/secureMessages.ts`, `genericSigning.ts`, `functions/sign.ts` |
| `pairing.ts` | `protocol/pairing.py` | `functions/connect.ts`, `functions/pair.ts` |
| `transport.ts` | `protocol/transport.py` | `api/rest.ts` |
| `client.ts` | `protocol/client.py` | `client.ts` |
| `calldata.ts` | `calldata.py` | `calldata/evm.ts` |
| `evm.ts` | `client.py` | n/a |

Crypto comes from `@noble/curves` (P-256 ECDH/ECDSA, secp256k1 recovery),
WebCrypto (AES-256-CBC; padding handled as documented in `secureChannel.ts`) and
viem (keccak, sha256, RLP, transaction serialization). There is no gridplus-sdk runtime dependency.

The module holds no persistent state. The caller supplies the P-256 app key
and a transport. The ephemeral key lives in memory, so each operation starts
with `connect()`.

Tests: `tests/lattice/`. Parity fixtures come from ape-grid-lattice
`tests/fixtures/fixtures.json`, generated by its `generate.js` with the same
npm libraries gridplus-sdk uses.
